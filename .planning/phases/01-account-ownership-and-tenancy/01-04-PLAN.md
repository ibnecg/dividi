<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| CLI → linked Supabase project | A migration crosses from reviewed repository SQL into persistent hosted state. |
| Browser credentials/cookies → Next.js/Supabase Auth | Untrusted credentials and potentially stale cookies drive session changes. |
| RLS organization result → private UI | Only complete caller-owned data may render into the workspace shell. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-15 | Tampering | remote schema push | high | mitigate | Local reset/tests, explicit development project reference, migration-list check, and post-push type comparison before auth verification. |
| T-01-16 | Spoofing | sign-in/session refresh | high | mitigate | Supabase password auth plus trusted user verification at protected boundaries; refresh proxy propagates provider cookies only. |
| T-01-17 | Information disclosure | cached/private workspace | high | mitigate | Dynamic authenticated routes, no stale partial rendering, and logout/back/refresh smoke checks. |
| T-01-18 | Tampering | Server Actions | high | mitigate | Server Zod parsing and fresh identity/RLS query inside each exported action; no client-selected tenant redirect. |
| T-01-19 | Information disclosure | foreign organization | high | mitigate | RLS-empty result and identical neutral not-found UI for missing/foreign identifiers. |
| T-01-20 | Information disclosure | CLI/runtime secrets | critical | mitigate | CLI-only secret env vars, publishable app key only, no credential echo, and source scan inherited from Plan 01-02. |
| T-01-SC | Tampering | package-generated UI | high | mitigate | Dropdown/Avatar come only from the human-approved official shadcn registry set; no new install surface. |
</threat_model>
