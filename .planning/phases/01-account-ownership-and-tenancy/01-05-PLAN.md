<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Public recovery form → Supabase Auth | Email values can be used to probe account existence or abuse email delivery. |
| Email callback → authenticated recovery session | Provider codes and redirect destinations can be missing, replayed, or tampered with. |
| Client form state → rendered auth UI | Errors and retained values can disclose credentials/provider internals. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-21 | Information disclosure | password-reset request | high | mitigate | Fixed sent-if-present response for known/unknown emails and generic provider failure handling. |
| T-01-22 | Spoofing / Tampering | recovery callback | high | mitigate | Provider PKCE exchange, safe-local destination validation, and valid recovery session required before update. |
| T-01-23 | Information disclosure | auth action/form state | high | mitigate | Never return passwords/raw provider errors; preserve only safe non-secret values and render generic alerts. |
| T-01-24 | Denial of service | reset email requests | medium | accept | Phase 1 uses provider behavior and server validation; product rate limiting is explicitly Phase 5, while the UI disables duplicate in-flight submission. |
| T-01-25 | Elevation of privilege | password update action | high | mitigate | Fresh server-side session validation and Supabase Auth update; no client identity/tenant fields accepted. |
| T-01-26 | Information disclosure | foreign tenant during full UAT | high | mitigate | Repeat pgTAP and hosted neutral-not-found smoke before phase completion. |
| T-01-SC | Tampering | package surface | high | mitigate | No new packages; reuse only the Plan 01-01 approved/locked dependency set. |
</threat_model>
