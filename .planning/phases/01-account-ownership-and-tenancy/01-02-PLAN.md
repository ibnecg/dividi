<interfaces>
The plan creates these contracts for all later work:

- `createClient(): SupabaseClient<Database>` in separate browser and server modules; the server variant owns the cookie adapter.
- `updateSession(request: NextRequest): Promise<NextResponse>` refreshes cookies but performs no tenant authorization.
- `requireVerifiedUser(): Promise<User>` validates a current Supabase user and confirmed email at protected server boundaries.
- `safeLocalPath(value: string | null): string | null` accepts only an allow-listed app-relative destination and rejects external/protocol-relative values.
- `AuthActionState` and `OrganizationActionState` expose field errors and one generic form error without passwords, provider errors, user IDs, roles, or organization IDs.
- `createOrganizationAction(previousState, formData)` accepts `name` only, invokes `create_organization`, and redirects to `/admin/organizations/{id}`.
- `create_organization(input_name text)` derives `auth.uid()`, returns the caller's single organization, and atomically establishes its owner membership.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser → Server Actions/Route Handler | FormData, redirect query values, and cookies are untrusted input. |
| Next.js server → Supabase Auth | Identity, confirmation, and session-cookie lifecycle cross into the external Auth service. |
| Authenticated PostgREST/RPC → Postgres | Caller JWT enters the database where RLS and function grants enforce tenancy. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-03 | Spoofing | `requireVerifiedUser`, SSR cookies | high | mitigate | Use trusted `getUser()`/validated claims and confirmed-email state at every protected boundary; never authorize from a cookie-loaded session object alone. |
| T-01-04 | Tampering / Elevation of privilege | `createOrganizationAction`, `create_organization` | high | mitigate | Zod accepts only name; RPC derives `auth.uid()`, pins search path, owns role assignment, and grants execute only to authenticated callers. |
| T-01-05 | Information disclosure | foreign workspace route | high | mitigate | Membership RLS returns zero rows and the server component calls `notFound()` with identical neutral copy per D-13 and D-15. |
| T-01-06 | Elevation of privilege | `organization_members` | high | mitigate | Revoke direct app-role mutation, make membership the D-14 source of truth, and expose no client field that selects tenant or role. |
| T-01-07 | Tampering | auth callback `next` | high | mitigate | Unit-tested `safeLocalPath` allow-list plus generic failure redirect prevents open redirect/session confusion. |
| T-01-08 | Information disclosure | browser bundle and env | critical | mitigate | Runtime source uses only publishable configuration; source assertion blocks privileged key material in `src`. |
| T-01-09 | Tampering / Elevation of privilege | anonymous/client writes | high | mitigate | RLS, grants, and RPC execute policy deny anonymous organization/membership writes and arbitrary authenticated membership writes. |
| T-01-SC | Tampering | npm/shadcn installs | high | mitigate | Plan 01-01 blocking approval is a precondition; install exact approved versions and preserve the lockfile. |
</threat_model>
