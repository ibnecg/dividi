<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Lifecycle controls to Server Actions | Untrusted campaign IDs and repeated commands cross from the browser. |
| Lifecycle RPC to campaign/audit data | Status mutation and retained evidence must commit atomically under owner authorization. |
| Audit rows to browser DTO | Retained metadata crosses into UI and must exclude sensitive recipient/foreign data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-15 | Tampering | Campaign status transitions | high | mitigate | Four narrow RPCs, row locks, explicit transition matrix, publish prerequisites, and no direct status DML. |
| T-02-16 | Repudiation | Lifecycle audit | high | mitigate | Same-transaction trigger with auth-derived actor and immutable owner-visible events. |
| T-02-17 | Elevation of privilege | Campaign UUID commands | high | mitigate | Reauthorize in every action and RPC and test foreign/anonymous neutral denial. |
| T-02-18 | Information disclosure | Audit DTO | medium | mitigate | Select/map only safe structural fields, owner RLS, neutral not-found, and no raw PIX metadata. |
| T-02-SC | Tampering | Package supply chain | low | accept | This plan installs no package and leaves package manifests and lockfiles unchanged. |
</threat_model>
