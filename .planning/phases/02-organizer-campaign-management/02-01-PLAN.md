<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser to Server Action | Untrusted FormData, slug, and creation token cross into authenticated server code. |
| Server Action to Supabase RPC | A user-scoped client invokes a database command that must derive tenant and role independently. |
| RPC to campaign table | Security-definer code crosses RLS/grant boundaries and must use a pinned empty search path and qualified relations. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-01 | Elevation of privilege | `create_campaign_draft` | high | mitigate | Derive `auth.uid()`, require owner role in the database, reject client tenant/role fields, and test foreign/member/anonymous denial. |
| T-02-02 | Tampering | Draft identity and duplicate submission | high | mitigate | Normalize/bound inputs, revoke direct mutations, serialize by owner, and enforce unique token and slug indexes. |
| T-02-03 | Information disclosure | Campaign select/error path | high | mitigate | Grant no anonymous read, rely on owner RLS, and map database failures to one generic message. |
| T-02-SC | Tampering | Package supply chain | low | accept | This plan installs no package and leaves package manifests and lockfiles unchanged. |
</threat_model>
